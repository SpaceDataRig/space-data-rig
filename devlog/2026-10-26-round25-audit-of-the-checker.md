AUDIT 25: we pointed the audit at the audit machinery, and the defect we found was in our own checker.

The gate in question decides which of the 56 reports on spacedatarig.app may be called machine-checked. It re-hashes each report's recorded inputs against the files the repository actually carries, and publishes verified / stamped / unattested counts. Round 23 quoted those counts publicly, so this is the surface a reader was leaning on.

Method, same as always: recompute the artifact's summary without importing the code that produced it, then make the failure happen on purpose.

1. Our independent recheck was blind to one of the two ways a stamp is written. Generators record it in two shapes: nested under meta, or flat at the top level. The recheck read only the nested shape, so it printed "stamped=15, disagreements=0" against an index publishing 17 -- and the two rows it never opened were the two rows we had sent it to investigate. Worse, the mismatch showed up in its own output and we explained it away in prose instead of flagging it. It also skipped any row whose file it could not open, so a claim of verification over a missing artifact would have scored as agreement. It now resolves both shapes, puts each row in a named bucket, compares its counts against the published ones, and exits non-zero on any disagreement: rows=56, opened=54, absent=2, stamps 17/17, verified 16/16.

2. The site's honesty mark was fail-open. Reports the gate could not check are supposed to carry a visible "provenance unverified" badge -- 40 of the 56 rows rely on it. The predicate fired only on an explicit false, so a row whose verified field was merely absent rendered with no mark at all and read as clean. The mark now has to be earned: it shows unless verified is exactly true. Nothing in the test suite had run that code; the predicates are now lifted out of the served file and run against a truth table and against the real published index.

3. The alarm had never been heard. The gate's publish-time half -- the refusal exit, the red banner, the stale entry written into the index -- was covered only by assertions on a committed artifact that happened to be clean, which proves nothing about the next stale report. A drill now builds a throwaway git repo, runs the real script, tampers one tracked input, and requires exit 1 naming the report. A second case requires the red mark to survive the flag that the only CI publisher passes by design, because on that path the public guarantee is the mark, not the refusal.

4. Our own receipts were in a directory git ignores. Three separate handover entries promised a measurement script as the tripwire, and three times that script lived under a path no clean checkout contains -- computed but not published, the exact defect this gate exists to catch, aimed at our own audit trail.
