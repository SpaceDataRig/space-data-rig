How to read this (plain English)
  • Period - the planet's "year": days between dips.
  • Depth (ppm) - how much the star dims, parts per million.
  • SNR - signal strength; above ~7 we trust it over noise.
  • Confidence - % of times the signal survives a fresh-noise replay.
  • Significance (FAP) - the odds that plain noise on THIS star alone could fake a dip this strong; a lower number is more believable, and we reject above 0.05.
  • Blind verdict - the judge ruled on the evidence without being shown the expected answer; "confirmed" here means the pipeline recovered a known signal, not that it found a new planet.
  • Bundle hash - fingerprint of the whole analysis; same inputs, same hash.
  • On-chain - that hash on Solana mainnet, a public timestamped proof.

MISSION BRIEF

what this rig is, what is real, and how to audit it

Space Data Rig is an autonomous exoplanet science console. A chair plus five specialist agents (fetch, scout, sim, critic, reporter) run a real analysis pipeline, debate every candidate in the open around a 3D round table, seal each verdict into a reproducible bundle, and anchor its hash on Solana mainnet so no result can be quietly rewritten.

What is real

  • Target catalog — queried LIVE from the NASA Exoplanet Archive (TAP table pscomppars) on every non-offline run; the source is stamped into each bundle manifest.
  • Light curves (curated) — for targets in the curated registry, real MAST TESS 2-min photometry is downloaded anonymously and FITS-parsed; every entry is re-checked by npm run mast:validate.
  • Analysis — BLS transit search, odd-even alias checks and injection-recovery confidence are computed here on every run, never asserted.
  • Proof — each finding ships a reproducible bundle (plots + manifest); its SHA-256 is written on-chain, and the Verify button re-hashes it from cold storage.

What is simulated, on purpose

  • Light curves (fallback) — for targets not in the curated registry, seeded reproducible stand-ins built from the real catalog parameters (period, radii, depth). Same seed, same curve, on any machine. Each finding card labels which tier produced its photons.
  • The table — the six minds are software agents; with a chat key configured the critic adds live model commentary, otherwise every line is grounded in the computed numbers.
  • Blind critic — the reviewer decides from the evidence alone (signal strength, a per-star calibrated significance, transit shape, coverage). The known period is compared only afterwards and never steers the verdict, so a “recovered” label measures pipeline reliability, not a new detection.

Audit it yourself

  1. Open a card's NASA archive row link and compare period / depth with the card metrics.
  2. Hit Verify: the bundle hash is recomputed from the stored artifacts.
  3. Open the tx link: the on-chain memo carries that exact same hash.

HOW WE MAKE SURE WE ARE NOT FOOLING OURSELVES

four guards, in everyday words

Realistic noise

Real starlight is not clean. It drifts slowly, like a shaky hand, not just random jitter. We add that same "stickiness" on purpose, so a signal only counts if it survives messy data rather than textbook-perfect data.

A fair bar per star

A jittery star and a calm star should not be judged by one ruler. We measure each star's own wiggle and ask: "could plain noise on THIS star have faked this dip?" We only believe a dip when the answer is comfortably no.

A blind referee

The judge is not told the right answer. It rules on the evidence, and we check against the known answer only afterwards. So a "recovered" result proves the pipeline really works, without ever peeking at the solution.

Is it this star, really?

A dip can come from a fainter neighbour blended into the same pixel. On real images we check that the dimming is centred on the target star, and we reject the find if the light that faded is somewhere else.

Every result is sealed into a reproducible bundle and its fingerprint anchored on Solana mainnet, so the numbers on this page cannot be quietly edited after the fact. This is a self-test of the method on real data — it does not claim to have discovered new planets.

WE CHECKED OURSELVES AGAINST THE REAL SKY

three honest tests, on real star data

Our noise model matches reality

We assume a star's shimmer fades in a specific, predictable way. Checking that against real starlight, the calm stars are calm and the twitchy ones fade just as fast as our model says — never slower. So our "could this be noise?" test is honest, not secretly too trusting.

We re-found real planets blind

Given only the raw pixels, and never told what to look for, we independently recovered the orbit of about 4 in 10 still-unconfirmed candidates — getting their timing right to well under 1%. We miss the slow, long-orbit ones on purpose: one short snapshot cannot prove them.

We measure depth, and size

Drawing the true shape of a transit — not just a box — pins its depth to about 12% on well-observed planets, more than twice as sharp as the quick estimate. Because the depth tells us how wide the planet is, the same fit recovers a planet's SIZE (how many Earths across) to within a few percent. We publish the error bars, and admit they get too optimistic when a star is very active.

These are checks of the METHOD on real, already-known data, run on freely published telescope products. They show the pipeline is trustworthy; they are not a claim of any new world.
